# 香港主体开户材料信息提取工具

本地运行的香港主体（CI / BR / NNC1·NAR1 / 董事护照）材料信息提取工具。上传
四类 PDF，自动提取企业信息、企业代表（董事）与 UBO（最终受益人，持股
≥25%），前端逐字段复核编辑后导出 JSON / CSV。详见 `PRD_HK_主体材料提取.md`
（产品需求）。

## 目录结构

```
app/
  main.py                FastAPI 服务：静态页面 + POST /api/extract
  extraction/
    schema.py             字段对象（value/source/status/raw）
    normalize.py           日期归一化、地址推断国家等工具函数
    pdf_text.py             文字层提取（pdfplumber 逐词坐标重建版面）+ OCR fallback（pdf2image/pytesseract）
    ci.py / br.py            CI / BR 的正则/关键词锚定规则
    nnc1.py                  NNC1/NAR1：注册地址、股东/UBO（正则锚定）；董事
                             字段优先走 pi_nnc1.py 的坐标裁剪，找不到 PI-NNC1
                             页时才回退到本文件内的正则锚定逻辑
    pi_nnc1.py               PI-NNC1 董事受保护资料页：按坐标裁剪取值（见下）
    registered_office.py     NNC1/NAR1 第3节「註冊辦事處」地址：按坐标裁剪
                             五个分栏，复用 coord_text.py 的锚点搜索/裁剪
    coord_text.py            pi_nnc1.py 与 registered_office.py 共用的坐标
                             搜索/裁剪基础函数（不含具体字段标签词表）
    person_fields.py         nnc1.py 与 pi_nnc1.py 共用的姓名/证件/地址字段
                             组装逻辑（拼音兜底、状态包装、地址拼接顺序判断
                             ——见下），与取值方式无关
    passport.py               护照机读区（MRZ）提取：性别/出生日期/完整证件
                             号权威来源，NNC1/PI-NNC1 均不含前两项（见下）
    romanize.py              中文姓名转拼音兜底（普通话拼音 / 粤语拼音建议）
    merge.py                跨文件合并、默认值、派生字段、冲突检测
static/
  index.html               前端页面（基于 hk_extract_ui.html 原型改造，接入真实后端）
requirements.txt
```

## 环境依赖

- Python 3.10+
- 系统层：`tesseract-ocr`（含繁体中文语言包 `chi_tra`）、`poppler-utils`（供
  `pdf2image` 使用），仅扫描件走 OCR 时才需要。

Ubuntu/Debian 安装系统依赖：

```bash
sudo apt-get install -y tesseract-ocr tesseract-ocr-chi-tra poppler-utils
```

macOS（Homebrew）：

```bash
brew install tesseract tesseract-lang poppler
```

## 安装与运行

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

打开浏览器访问 `http://localhost:8000`，四栏上传 CI / BR / NNC1·NAR1 / 护照
（董事证件）PDF，点击「开始提取」。

## 说明与已知限制

- **提取规则为启发式实现**：CI/BR/NNC1/NAR1 的官方表格版式在不同年份、不同
  申请渠道下略有差异，`app/extraction/ci.py`、`br.py`、`nnc1.py` 中的正则
  基于公开表格的常见字段标签编写，尚未用真实样本校准（对应 PRD 第 10.5
  条待确认项）。建议用脱敏真实样本跑一遍，按需调整锚点正则。
- **企业代表字段范围**：不提取/展示职位、国籍、居住国家（NNC1/NAR1 中经常
  缺失或需要额外证件比对，暂不纳入）。性别、出生日期专门由护照上传窗口提
  供（见下）；居住地址、证件信息优先从 PI-NNC1 取（见下），护照证件号更
  权威时会覆盖。
- **护照机读区（MRZ）提取：性别/出生日期/完整证件号权威来源**（对应 PRD
  第 10.1 条）：NNC1/PI-NNC1 完全不含性别、出生日期栏位，董事证件号也常
  缺失或遮蔽。`passport.py` 从护照上传中提取这三项，按英文姓名匹配到对应
  董事，权威覆盖（即使 NNC1 已有证件号也以护照为准，因为表格上的常是部分
  遮蔽值）。护照生活资料页是照片而非文字层 PDF，必须走 OCR——但与扫描版
  CI/BR 不同，护照可视资料区（姓名/性别/出生日期等填写框）叠印着全息安全
  底纹，Tesseract 在任何 PSM/DPI 下读出的都是接近纯噪声；底部的机读区
  （MRZ，两行 OCR-B 等宽字体）没有这层底纹，OCR 干净得多，且 ICAO 9303
  TD3 格式固定 44 字符、位置定死，不需要靠标签匹配、按位置切片即可解析。
  因此 `passport.py` 完全依赖 MRZ，不解析可视资料区。定位 MRZ 本身是难点
  ——扫描/拍照的取景比例每份都不同，固定裁剪比例只对一张照片的构图有效，
  因此在图片下半部分尝试若干候选水平条带、逐条 OCR，直到两行样子像 MRZ
  （长、几乎全是 `[A-Z0-9<]`、有填充用的"<"）的文本出现为止。找不到 MRZ
  时对应字段一律留空待人工补录，不猜测。此逻辑已用真实用户提供的护照原
  件逐字段校验到完全一致（证件号、姓名、性别、出生日期、签发国均正确）。
- **PI-NNC1 董事受保护资料页：坐标裁剪取值**：PI-NNC1（首任公司秘書／董事
  (自然人)- 受保護資料，指明編號 1/2023）是公司注册处的固定版式模板，同一
  份字段在不同文件中的坐标基本不变。`pi_nnc1.py` 不再对整页拉平后的文字流
  跑正则，而是：
  1. 在文档各页中找到页首含"PI-NNC1"且含"Protected Information／受保護
     資料"的那一页，作为董事受保护信息页（一页对应一位人士，多位董事对应
     多页）；
  2. 用 `page.extract_words()` 定位每个字段英文标签的文字坐标作为锚点（英
     文优先：真实样本里遇到过中文标签字形损坏（大廈→大度、國家→囫家）、
     "Surname"被读成"Sumame"等个别文件的字体子集化问题，中文/其他拼写留
     作锚点找不到时的备选，never 作为唯一依赖）；
  3. 从锚点位置向其填写值所在的行、列偏移，用 `page.crop()` 裁出一个小矩
     形区域再 `extract_text()`，横向范围严格限定在该字段值列内（不会越界
     碰到隔壁栏位或标签文字），纵向范围基于前一个已定位字段的位置动态收
     紧，标签找不到时回退到按页面高度比例估算的位置，但仍限定在同一栏位
     内——同一段说明文字里偶然出现"香港身分證""通常住址"字样不会被当成
     字段标签。
  证件号逻辑不变：香港身份证栏为空/NIL/「無」时改取护照完整号码 + 签发国
  家/地区；通常住址仍是 Flat/Floor/Block、Building、Street、District/City/
  Province、Country 五栏非空值按顺序拼接，缺栏跳过、不留空隙、不会把栏位
  标签拼进去。此逻辑已用真实用户提供的两份不同公司的 NNC1 原件（含空白
  Flat/Building 分栏、上述字形损坏等版式）逐字段校验到完全一致；同时保留
  `nnc1.py` 内基于正则锚定的旧实现作为兜底——扫描件（文字层是 OCR 词框重
  建出来的，不是原生坐标）或找不到 PI-NNC1 页的文件会自动走这条路径。
- **已知限制：新版式 Section 5/6 股权表格**：部分真实 NNC1 的「Share Capital
  and Initial Shareholdings」与「創辦成員 Founder Members」表格表头跨多行
  换行排版，版面重建后字段标签与其数字之间隔着好几行无关表头文字，现有
  正则（本次未改动，按 PRD 要求保留）定位不到，会导致这两节解析不到股东/
  总股本、UBO 列表为空。董事本人字段（PI-NNC1 页）不受影响。曾尝试放宽这
  段的窗口搜索来兜住这种情况，但在真实样本上算出了 202300% 这种明显错误
  的持股比例（宽窗口套到了不相关的数字/字段上），已撤回改动——UBO 列表宁
  可留空待人工补录，也不能算出一个假的持股比例。
- **NNC1/NAR1 註冊辦事處地址：坐标裁剪取值**：与 PI-NNC1 页同理，第3节
  「公司在香港的註冊辦事處的建議地址」也是固定版式的五个分栏（室/樓/座、
  大廈、街道、區、地區），`registered_office.py` 用与 `pi_nnc1.py` 相同的
  锚点搜索+坐标裁剪方式取值，不再依赖文字流的自然顺序——真实样本里，
  pdfplumber 按内容流顺序读出的地址是「A座15樓01室A133 華生大廈 黃竹洋街
  14至18號 火炭 香港」（顺序颠倒），坐标裁剪后按各分栏定位重组正确。
- **地址拼接顺序按内容语言判断**：五个地址分栏组装成一行时，若内容以中文
  为主，按中文地址习惯"由大到小"顺序（國家 → 地區/市/省 → 街道 → 大廈 →
  室/樓/座）直接拼接、不加分隔符（如"香港火炭黃竹洋街14至18號華生大廈A座
  15樓01室A133"）；若以英文/拉丁字符为主，则按西方地址习惯"由小到大"顺序
  （Flat → Building → Street → District → Country）、逗号分隔（如"FLAT
  2304, 23/F, ... Hong Kong"）。判断依据是五个分栏实际内容里 CJK 字符占比，
  不是按字段固定死一种顺序——因为同一个分栏（无论是註冊地址还是董事住址）
  在不同文件里可能填中文也可能填英文。`person_fields.assemble_address()`
  统一处理，`pi_nnc1.py`、`registered_office.py` 都调用它。
- **CRN 交叉验证**：CI 的公司注册编号应与 BR 登记证号码的前段数字一致（同
  一法人实体）。`merge.py` 在两者都存在且不一致时记一条 `conflicts` 提醒人
  工复核，不自动判定谁对谁错——常见原因是扫描件 OCR 把某一位数字读错（如
  0/O、6/G 混淆）。
- **英文姓名拼音兜底**：若原件英文姓名（Surname / Other Names）留空但有中
  文姓名，会按该董事证件类型自动填充拼音建议：证件为中国大陆身份证/护照
  （签发国 China）时，用 `pypinyin` 转普通话拼音，标记为「推断值」；证件为
  香港身份证时，用 `pycantonese` 的粤拼再套用一份近似的"香港身份证英文拼
  法"映射表生成建议值，标记为「建议值·待确认」（不是「推断值」）——因为香
  港身份证英文姓名并无统一转换标准，只能作为待人工核对的建议，不可当作确
  认值使用。两种拼音都会在导出的 JSON/CSV 中带上明确的 source/status，方便
  区分。
- **UBO（最终受益人）计算方式**：不直接找现成的持股比例文字，而是分别定位
  NNC1 第 5 节「Share Capital and Initial Shareholdings」Total 行的股份总数
  （分母）与「創辦成員 / Founder Members」股东名单里各股东的认购股数
  （分子），相除算出百分比，仅保留 ≥25% 的股东列入 `ubos`。法人股东（公司）
  只登记公司名称与持股比例，不追溯其背后自然人。股东名单区块通常不重复
  证件/地址信息，若该股东同时也是董事，会自动从董事记录回填。无法定位股份
  总数时，相关股东仍会列出但持股比例标记「缺失待补」，不会静默丢弃潜在
  UBO。此逻辑同样是启发式实现，未经真实 NNC1/NAR1 样本校准。
- **文字层版面重建**：`pdf_text.py` 不使用 pdfplumber 默认的 `extract_text()`
  （其阅读顺序基于 PDF 内容流的字符绘制顺序，在 PI-NNC1 这类多栏表单上会把
  标签与填写值错位穿插），而是用 `page.extract_words()` 取得每个词的
  x0/x1/top 坐标，按 `top` 聚类成行、行内按 `x0` 从左到右排序，行间用换行、
  同行跨列之间用加宽空白拼接，使"标签 → 右侧/下方值"的空间对应关系保留到
  输出文本里。OCR 分支同理，用 `pytesseract.image_to_data`（`--psm 6`）取
  词级坐标做同样的重建（坐标按 OCR_DPI 换算像素->点）。
- **叠印文字层去重**：部分翻印/扫描后重新生成的 BR/CI PDF 会把同一段文字
  的文字层原样重复嵌入两次、坐标完全重合，导致 pdfplumber 交替读出两层字
  符，每个字符看起来都重复了一遍（如"FLAT"→"FFLLAATT"）。`pdf_text.py` 在
  逐词重建版面前，先用 pdfplumber 内置的 `page.dedupe_chars()` 按坐标（而
  非纯文本模式）合并同文字、同字体字号、位置相差在 1pt 以内的重复字符，只
  保留一份——本来就该有的双字母词（如"KOMM"）因为不在同一坐标上，不会被
  误伤。
- **OCR 中文逐字加空格问题**：Tesseract 对中文没有类似英文单词间距的概念，
  `image_to_data` 会把每一个汉字当成独立的"词"，导致版面重建时相邻汉字之
  间被硬塞进空格（"香港"变成"香 港"），下游所有中文短语的字面量正则因此
  全部失配。`pdf_text.py` 的 OCR 分支在重建完每页文本后，会把两个中文字符
  之间的空白折叠掉（`_collapse_cjk_spacing`）——中文本来就不该有字内空格，
  这一步不会影响英文单词或中英文之间的正常间隔。
- **CI/BR 扫描件的真实版式坑**：用真实 Nexcloud Technology Limited 的扫描
  CI/BR 校准后修复的问题——
  - `ci.py` 公司名称正则原来漏加 `re.IGNORECASE`，只认全大写名称，而真实
    电子证书上的公司名是"Title Case"（如"Nexcloud Technology Limited"），
    导致扫描件永远抓不到名称；"I hereby certify that"的"I"常被 OCR 认成
    "|"，也已兼容。
  - `ci.py` 的成立日期锚点"incorporated...on"曾误配到"Hong**g**"中间的
    "on"子串（因为懒惰量词允许隔 80 个非数字字符），已加词边界修正；日期
    值本身改成"只锚定标签，交给 `normalize_date()` 解析一段较宽的窗口文
    字"，因为扫描件版面重建常把"Issued on 3 June 2026."拆成"Issued  3
    June\non  2026."（标签与数值分居两行、交替出现），原来要求日期三段连
    续无空行的正则无法处理这种错位。
  - `br.py` 的登记证号码原先只认"标签紧跟数字"，但真实 Form 2 表格表头
    「登記證號碼」与「費及徵費」两个相邻表头格在扫描件版面重建后连成一
    片、中间也没有数字，实际号码要再往下好几行才出现；现改为按号码本身
    的形状（CRN-000-YY-YY-N）直接搜索作为兜底。地址标签匹配原本要求出现
    在行首，真实扫描件里前一栏的英文标签尾巴（"Branch Name"）会和"地址"
    连在同一重建行里，已放宽为"行内前 20 字符以内"；OCR 把表格竖线误读成
    "!""|"、把"Address:"读成"Addre:"等版面噪声，取值时会先清洗掉。
- **OCR 依赖系统二进制**：若未安装 `tesseract-ocr` / `poppler`，扫描件文件
  会在结果中带上警告文案，字段按未识别处理，不会导致整个请求失败。
- 前端所有字段值可编辑；用户手动填写过的「缺失/遮蔽」字段会标记为「人工
  填写」徽章，一并写入导出的 JSON / CSV。
